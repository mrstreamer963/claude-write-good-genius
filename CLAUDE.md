# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Проект ведётся на русском: документация, комментарии, doc-комментарии и сообщения коммитов —
по-русски; идентификаторы и имена тестов — по-английски. Держись этой конвенции.

## Команды

```bash
make setup   # один раз: rustup target add wasm32-unknown-unknown + npm install
make dev     # собрать WASM и поднять dev-сервер на :5173
make build   # продакшн-сборка (WASM + статика в web/dist)
make wasm    # только пересобрать ядро в web/src/wasm
make help    # список целей
```

Тесты ядра гоняются на хосте (не в wasm), обычным cargo:

```bash
cargo test
cargo test demolish              # по подстроке имени
cargo test whole_room_is_erased_completely -- --nocapture
```

Форматирование — `cargo fmt`. Сборка под wasm требует cfg-флага `getrandom_backend="wasm_js"`
из `.cargo/config.toml` — без него линковка падает; файл не удалять.

⚠️ После `make wasm` под уже запущенным Vite фронт может отдавать старую wasm-обёртку из кэша.
Перезапусти `make dev` (или почисти `web/node_modules/.vite`).

## Архитектура

Три слоя, симуляция авторитетна и детерминирована, JS — «тонкий» вид без игровой логики:

- **`src/`** — ядро по модулям; `lib.rs` держит только крейт-док, сборку модулей и `pub use Sim`.
  Данные: `ruleset` (YAML → структуры) · `map` (тайлы, проходимость, версия) · `path` (BFS) ·
  `components` (компоненты ECS и ресурсы, без поведения). Поведение: `schedule` (цепочка тика) ·
  `jobs` (чертежи) · `hauling` (перенос лома: подвоз на площадку и уборка на склад, работа делится по остатку) ·
  `movement` (шаги, приказы, выход из пустоты) · `demolition` (порядок сноса) ·
  `skills` (навыки: рост от работы, скорость работы, обучение у парты и врождённый предел) ·
  `needs` (усталость: два порога, отдых, переезд упавшего, потолок сна и дремота) ·
  `food` (голод: сытость, поход за пайком, вдвое горящая бодрость) ·
  `health` (здоровье: ранение на вылазке, лазарет, работа медика и аптечка-расходник) ·
  `research` (наука: тема, лаборатория, технология) · `timeline` (события по расписанию) ·
  `missions` (вылазки: набор отряда, уход через шлюз, возвращение с добычей, плен и вылазка
  за своим; там же репутация заказчика и пострадавшего — §12.43) ·
  `gear` (снаряжение: комплект по шаблону, за которым кот идёт сам) ·
  `crafting` (производство: заказ, мастерская, предмет под ноги) ·
  `trade` (внешний рынок: курс по расписанию, покупка с доставкой, продажа через подвоз).
  `save` (сохранение партии: снимок мира, отпечаток рулсета, отладочный журнал команд).
  Наружу: `snapshot` (DTO) · `sim` (`#[wasm_bindgen]`-фасад). Модули приватные, публичен один `Sim`,
  поэтому внутрикрейтовые элементы помечаются `pub(crate)`.
- **`web/src/worker.js`** — WebWorker: фиксированный тик, `BASE_TPS = 6` тиков/сек на ×1,
  скорость (0·1·5·10) = множитель тиков в реальную секунду.
- **`web/src/main.js`** — PixiJS-рендер и ввод. Логики нет, только команды и отрисовка снапшота.
  ⚠️ Панели перерисовываются каждым снапшотом целиком (`innerHTML`), поэтому **кнопки внутри
  них вешаются делегированием на контейнер, один раз** (`onPanelClick`) и ловятся парой
  `mousedown`/`mouseup`, а **не** `click`. Узел кнопки живёт один кадр, а клик человека — сотню
  миллисекунд, и `click` браузер отдаёт ближайшему общему предку, то есть контейнеру: у такого
  события `target` — сам контейнер, и `target.closest('.mission-cancel')` не находит ничего.
  Так дважды умирали «Отменить» у заказа, «Бросить» у темы и «Отозвать» у вылазки: первый раз
  из-за обработчика на самом узле, второй — из-за проверки `target` в делегированном `click`.
  Новая кнопка в панели обязана идти через `onPanelClick`, а не через свой `addEventListener`.
- **`assets/rulesets/core.yaml`** — контент в стиле OpenXcom Extended. Лежит вне `web/`;
  Vite раздаёт его через `publicDir: '../assets'` как `/rulesets/core.yaml`.

Протокол `postMessage` (полный снапшот каждый кадр — сознательное упрощение, §12.8a). Палитры
(тайлы, предметы, навыки, параметры, перки, **фракции**, миссии, кандидаты, темы, рецепты) едут
один раз в `ready {meta}`; в снапшоте от них остаются индексы. **Наборы вида
`{имя: сколько}` (цена, добыча, `needs`) приезжают в JS как `Map`, а не как объект** — идиома
чтения одна на всех, см. `costChips` и `trustGap` в `main.js`; `Object.entries` на них молча
вернёт пусто.

**Цепочка систем одного тика** (`schedule.rs::build_schedule()`, `.chain()` — порядок значим):
`advance_time → collapse_exhausted → assign_heal → assign_eat → assign_rest → assign_treat →
assign_equip → gather_squad → assign_hauls → assign_research → assign_craft → assign_jobs →
mark_loose_scrap → assign_tidy → assign_nap → move_units → work_hauls → work_equip → work_eat → work_jobs →
work_research → work_craft → study → run_missions → run_timeline → run_trade → retry_orders → escape_voids →
spread_units → clear_solids → settle_stacks → sleep → doze → heal → tire → hunger → train_skills`.
Цепочка собирается тремя группами (`assign`, `act` и `settle`) только из-за предела арности
кортежа систем; порядок ровно тот же, что и одним списком.
**Фракции систем не заводят** (§12.43): репутация меняется в единственный момент — на
возвращении отряда, внутри `run_missions`, — как известность, и пустой системы для неё в цепочке
быть не должно.
`run_trade` стоит рядом с `run_missions` и `run_timeline` по той же третьей причине (§12.44):
купленное ложится кучей на шлюз, а тот мог стать ямой, — съехать на пол оно обязано тем же
тиком. **Продажи в `run_trade` нет вовсе**: её везут коты обычным подвозом, а деньги начисляет
`work_hauls` по мере сдачи; второго места, где считаются деньги, быть не должно.
Тесты гоняют ровно эту функцию, поэтому новую систему добавлять только сюда, а не в тестовую копию.
**Порядок одиннадцати раздатчиков = приоритет работ** (§12.15, §12.16, §12.20, §12.26, §12.30,
§12.34, §12.36, §12.37, §12.52): все берут котов из одного пула свободных, поэтому **ранение идёт первым** (§12.37:
остальные решают, чем кот займётся, а этот — что он вообще ничем заняться не может), еда — вторым
(§12.36: ходка за пайком короткая, а сон — сотни тиков, и уснувший голодным просыпается голодным),
отдых — третьим (иначе уставшего кота тут же уводит работа), **лечение — четвёртым** (§12.37:
пациент уже лежит, и каждый тик без медика — это котовремя, которого база лишилась), экипировка —
пятой (§12.34: на базе работа есть всегда, и поставленная после стройки она не случилась бы
никогда), подвоз на площадки — шестым (иначе за ломом никто не пойдёт, пока есть обеспеченная
работа), наука — седьмой (за тему уже заплачено образцами, а чертёж на базе есть почти всегда),
производство — восьмым (заказ размечен явно и поштучно), стройка и снос — девятыми, уборка пола —
десятой, а **дремота — последней** (§12.52: она раздаёт не работу, а её отсутствие, и «коту
ничего не досталось» становится фактом только после всех остальных).
`gather_squad` и `study` в этот порядок не входят:
и отряд, и ученика назначил игрок, и раздавать там нечего. `assign_equip` стоит **перед**
`gather_squad` и единственный берёт кота даже на маршруте, если тот в отряде: сбор ещё не
закончен, а уходить голым мимо лежащего комбинезона — это сила отряда, зависящая от расторопности
игрока (§12.34). `run_missions` стоит после
`move_units` (кот, шагнувший на шлюз, идёт в зачёт сразу) и до `settle_stacks` (добыча ложится на
шлюз, а он мог стать ямой); `study` — там же и по той же причине: кот, дошедший до парты, тикает
в этом же тике.

## Инварианты ядра

Это то, что ломается незаметно и чаще всего:

1. **Проходимость** — только построенный пол (индекс тайла `>= 0`); `-1` = пустота, непроходима,
   пересечь нельзя. Но `find_path` **не требует проходимости стартовой клетки** — на этом свойстве
   держится выход кота из ямы, менять сигнатуру осторожно.
2. **Детерминизм** — фиксированный timestep, фиксированный порядок `DIRS`, никакого рандома и
   wall-clock внутри систем. Любой недетерминизм ломает и тесты, и модель времени (§11).
3. **`BaseMap::version`** — единственный сигнал «карта изменилась»: одновременно гейт для
   `retry_orders` (не гонять BFS каждый тик) и триггер отправки `base_map` в рендер. Тайлы менять
   только через `BaseMap::set`, иначе версия не вырастет и оба механизма молча заглохнут.
4. **Снос идёт от глубины к берегу** (`DemolitionFront`), а не в порядке мазка мыши, и кот работает
   **с соседней клетки** — иначе он сносит пол под собой или отрезает себе доступ к остатку области.
5. **Приказ не срывает кота с начатой стройки**, но кот с *невыполнимым* приказом считается
   свободным для джобов — иначе он никогда не построит тайл, открывающий ему выход из запертой
   комнаты. Это была реальная регрессия; фильтры `Without<Assignment>` / `Without<Path>` в запросах
   `assign_jobs` и `retry_orders` подобраны именно под неё. **Спящего приказ тоже не срывает**,
   пока включено «Беречь себя» (§12.51, инвариант 10): `Order` висит, а маршрут ему проложит
   `retry_orders` в тик пробуждения.
6. **`stuck` — легальное состояние, а не ошибка**: кот замурован в пустоте или его приказ пока
   невыполним. Состояние обратимо (игрок ставит пол рядом) и только подсвечивается в UI.
   **Обратимость держится на `Order::tried_version`, и отмечает она провал, а не попытку.**
   Маршрут теряется не только от непроходимости: его снимают сон, рана и вылазка
   (`release_work`, `release_task`), карта при этом не меняется. Отмечай там попытку — и кот с
   выполнимым приказом остаётся «не может дойти» навсегда, пока кто-нибудь не построит тайл.
   Поэтому `set_target` и `retry_orders` ставят отметку **только на неудаче** и снимают её,
   как только маршрут нашёлся (`an_order_resumes_after_a_nap`).
7. **Занятость кота — это набор фильтров, а не флаг.** Задач уже одиннадцать (`Assignment` —
   стройка, `Haul` — перенос, `Rest` — отдых, `Study` — учёба, `Researching` — наука, `Crafting` —
   производство, `Equipping` — поход за снаряжением, `Eating` — поход за едой, `Healing` — лежит
   раненым, `Treating` — лечит раненого, `Squad` — отряд), и
   каждая новая обязана попасть во все места, где кот считается свободным: `assign_heal`,
   `assign_eat`, `assign_rest`, `assign_treat`, `assign_equip`, `assign_jobs`, `assign_hauls`,
   `assign_research`, `assign_craft`,
   `assign_tidy`, `retry_orders`, `Busy::of` (для `is_stuck` **и** для `job` — того, что игрок
   читает в карточке, §12.41), `spread_units`, `clear_solids`, `doze` (дремота не задача, но
   список «у кота нет ничего» читает целиком, §12.52),
   а также в оба места, где задачу отбирают: `release_task` (приказ игрока, заявка на вылазку) и
   `release_work` (усталость, §12.33; ранение, §12.37). Оба **отпускают, а не гасят claim**
   (§12.48): работу, которую держит claim у самой работы (чертёж, тема, заказ), они очищают явно,
   а подвоз — нет, потому что носильщик записан только у себя.
   Пропущенный `Without<…>` даёт не падение, а тихое перехватывание кота посреди работы или сна.
   Отдельно от них `Away` (кота нет на базе) режет `tire`, `hunger`, `escape_voids`,
   `collapse_exhausted` и рендер. **С §12.40 он стоит и во всех двенадцати раздатчиках**:
   пленный — это `Away` **без** `Squad` (отряд despawn'ится вместе с миссией), и фильтр по
   отряду отдал бы его первому же чертежу. «Нет на базе» — это `Away`, а не `Squad`.
8. **Ничего не остаётся в пустоте.** Кот выходит сам (`escape_voids`), куча лома сдвигается на
   соседний пол (`settle_stacks`, он же сливает две кучи на одной клетке). Правило одно на обоих:
   пустоту не пересечь, значит оставленное в ней недостижимо, — но кот виден флагом `stuck`,
   а лом молча пропал бы (§12.15). Той же природы `spread_units`: **пройти сквозь кота можно,
   остаться в его клетке — нет** (§12.32). Кот не входит в проходимость (иначе маршруты зависели
   бы от того, кто где стоит в этот тик), поэтому правило разбирается после факта, а не запретом
   в семи раздатчиках: остаётся занятый делом, при равенстве — первый по `id`, остальные шагают
   на свободного соседа. Отряд у шлюза — исключение: сбор по определению сводит котов в одну
   точку (§12.22).
   **Материал тоже не исчезает:** отмена площадки возвращает уже сданное кучей на её клетку
   (§12.31) — в лапах носильщика груз при этом остаётся у него. Той же природы §12.38: **заявка на вылазку
   роняет ношу кучей под ноги коту** — иначе лом уезжает в поле и на сотни тиков выпадает из мира
   (не взять, не разметить). Это единственное исключение из «ношу посреди базы не бросают», и
   граница у него ровная: приказ игрока груз не роняет (кот сходит куда велено и донесёт), а
   вылазка убирает кота с базы надолго. Роняет `Sim::launch` — единственное место, где
   назначается отряд.
   Той же природы `clear_solids` (§12.35): на клетке со свойством `solid` (стеллаж) **пройти
   можно, остаться нельзя**. Проходимость правило не трогает — иначе стеллаж отрезал бы себя от
   носильщиков, которым сдавать груз, стоя на нём; сходят только свободные и спящие, кто при
   деле — остаётся. **Два «после факта» упорядочены между собой** (§12.39): сойти с полки важнее,
   чем не встать вдвоём, поэтому свободного соседа нет — `clear_solids` сходит на занятого
   (наложение разберёт `spread_units`), а сам `spread_units` на заставленную клетку не отходит
   вовсе. Обратный порядок дал бы качели: согнали с полки → развели → загнали обратно.
   **Завал на полу замедляет шаг** тем сильнее, чем куча больше, до потолка
   (`CLUTTER_PER_TICK` / `CLUTTER_MAX` в `movement.rs`), и это второй смысл уборки. Считается
   только пол: сложенное в склад — порядок, а не завал. **BFS о завалах не знает** и не должен:
   он считает шаги, а не время, иначе коты обходили бы кучи, которые сами пришли разбирать, а
   «ближайший кот» в раздатчиках стал бы считаться иначе, чем видно на карте (§11, §12.35).
9. **Навык не влияет на выбор исполнителя, только на скорость работы.** Раздатчики берут
   ближайшего кота (§12.14); мастер на дальнем конце базы вернёт ровно ту беготню через
   полкарты, ради которой §12.14 и писалась. **Ничью «ближайший» не решает, и решать её
   порядком обхода ECS нельзя** (§11, §12.45): он зависит от истории вставок, а у мира,
   поднятого из снимка, она своя. Правило одно на все раздатчики — **коты по `id`, места и
   кучи по клетке**: либо ключ `min_by_key` включает их явно (`assign_equip`, `assign_research`,
   `assign_craft`), либо входные списки сортируются перед жадным перебором (`assign_jobs`,
   `assign_hauls`, `assign_tidy`, `assign_treat`). Новый раздатчик обязан делать то же. Работа считается в **очках**, а не в тиках
   (`BUILD_WORK` / `WORK_RATE`): при `progress += 1` минимальный шаг навыка — двукратное
   ускорение. Новая система работы обязана вешать `Worked(домен)` — иначе навык за неё молча
   не растёт, а начисляет опыт только `train_skills` в конце цепочки (§12.17).
   **Потолок опыта у каждого кота свой** (§12.42): врождённый параметр (`Stats`) режет предел
   уровня в домене — `demands` у навыка задаёт, сколько параметра нужно на 2-й, 3-й, … уровень
   (первый не закрыт **никогда**: список начинается со второго, и «домен недоступен» рулсетом
   невыразимо). Считается это одним местом — `skills::xp_ceiling`, и в него обязаны упираться
   оба источника опыта: работа (`train_skills`) и парта (`desk_cap` = ниже из `taught` и
   врождённого). Разойдись они — кот сидел бы за партой, которая ему ничего не даёт. Параметр
   **не пишет ни одна система**: две шкалы, двигающиеся одним действием, — это один навык под
   двумя именами.
10. **У бодрости два порога, и они забирают кота по-разному** (§12.20, §12.33). Выше `tired` кот
   работает; ниже — уходит спать, **но только свободным**: начатое дело обычная усталость не
   срывает, как не срывает его приказ игрока. Ниже `critical` срывает — и **только под свободную
   лежанку**: бросить дело и остаться стоять это ни сна, ни работы. На нуле кота роняет где стоит
   `collapse_exhausted`, откуда угодно и не спрашивая лежанки. Оба срыва **обязаны** явно
   освободить чертёж (`assignee`/`hauler`), пометку кучи, тему, заказ и парту — иначе площадка
   навсегда останется за спящим; поэтому освобождение живёт одной функцией (`release_work`) на
   оба случая. Второй порог выключается игроком (`AutoRest`), и выключение **никого не будит**.
   **Пока `AutoRest` включён, спящего не будит ни заявка на вылазку, ни приказ игрока**
   (§12.51): `Sim::launch` и `Sim::set_target` не зовут на него `release_task` и не трогают
   маршрут — пишут только своё (`Squad`, `Order`), а поведут кота `gather_squad` и
   `retry_orders`, когда он проснётся сам. Решение игрока при этом не теряется и второго клика
   не требует. Это единственные два места, где `AutoRest` читает фасад, а не `assign_rest`.
   `assign_rest` раздаёт лежанки тремя проходами по одному списку свободных мест, в порядке
   нужды: критически уставшие → уставшие → **упавшие** (они уже спят, но на полу — сон там
   вшестеро медленнее, и достроенная зона отдыха обязана их касаться, §12.33). Спать можно на
   любой клетке, лежанка лишь быстрее: скорость сна не бывает нулевой, иначе кот не проснётся.
   **Лежанку занимает один кот** — занятость держит `Rest::spot` спящего (а у упавшего — его
   позиция), поэтому снимается вместе с задачей; свободной нет — кот работает до упора. Делить
   лежанки нельзя: их число тогда ни на что не влияет (§12.20).
   **У сна есть потолок, и он свойство места** (§12.52): `wake` у тайла, `floor_wake` в
   `energy:` для всего остального; ноль значит «до полной». На потолке `sleep` снимает `Rest`,
   и дальше начинается **дремота** — кот лежит там же и добирает бодрость (`doze`), но задачи у
   него нет. Отсюда всё её поведение: её видит любой раздатчик, её не защищает §12.51, лежанку
   она не держит (`assign_rest` считает занятыми только места спящих), а сгоняет дремлющего с
   кровати пришедший спать — обычным `spread_units`. Своего компонента у дремоты нет и заводить
   его нельзя: она и есть «нет задачи + место для сна под лапами».
   К свободной лежанке кота отправляет `assign_nap` — **последний раздатчик** и единственный, кто
   выдаёт не задачу, а маршрут. Идёт кот **по шагу за тик**, а не целым маршрутом: с `Path` он
   невидим раздатчикам (инвариант 5), и дорога через полбазы означала бы простой освободившегося
   чертежа. Занятой при этом считается и клетка под котом, и та, куда кто-то идёт, — иначе двое
   выберут одну лежанку и разойдутся качелями (§12.39).
   **Пошагово идущий останавливается только там, где имеет право стоять** — не на полке (§12.35)
   и не под остановившимся котом (§12.32). Шаг за тик значит остановку на каждой клетке
   маршрута, а обе эти разбираются после факта: замер — согнали — пошёл снова, и коты мечутся
   между стеллажами (реальный баг, §12.52). Поэтому шаг растягивается до ближайшей клетки, где
   замереть можно. Любая будущая пошаговая ходьба обязана делать то же.
11. **Лом не исчезает с пола «в лапы».** Кот поднимает кучу, только если знает, куда её деть, и
   берёт не больше, чем влезет в адресат. Груз в лапах игроку не виден как ресурс и не
   размечается — то, что лежит на полу, всегда можно достать (§12.16). Сумма
   «кучи + лапы + `delivered`» сохраняется; на ней держатся тесты уборки.
   **Отсюда и правило раздачи по остатку** (§12.48): носильщиков у адресата столько, на сколько
   хватает недостачи, но берущий с кучи обязан вычесть чужой груз в пути (`less_incoming`) —
   иначе второй кот поднимет уже везомое, на месте этого никто не ждёт, и лишнее осядет в лапах.
   Из двух промахов лишняя ходка дешевле (§12.15), поэтому место на складе режет уборку заранее,
   а **за какой кучей и за каким типом кот пошёл, записано наводкой** (`Haul::aim`, §12.49) —
   по ней обе раздачи считают обещанное. Наводка **не бронь**: подъём её не читает, кот берёт
   что под ногами, и пропавшая куча остаётся промахом ценой ходки.
   **Единственное место, где предмет законно исчезает из мира, — продажа** (§12.44): товар
   уходит прямо из лап в момент сдачи на шлюзе и **кучей не становится ни на тик**. Это не
   мелочь: `mark_loose_scrap` метит на склад всё, что лежит на клетке без ёмкости, а у шлюза
   ёмкости нет, — полежи проданное хоть тик, уборка увезла бы его обратно. Свойство держит
   ветка `HaulTo::Sale` и тест, проверяющий шлюз на каждом тике.
12. **Тип предмета — индекс палитры `items:`, и он лежит в куче, в грузе и в цене тайла.** Цена —
   **набор** `(предмет, сколько)`, упорядоченный по имени предмета (`BTreeMap` в рулсете): порядок
   доходит до раздачи задач, а `HashMap` сделал бы её недетерминированной. Кот везёт **один тип за
   ходку**, кучи разных типов лежат на одной клетке и не сливаются, а склад типо-агностичен —
   ёмкость считает штуки (§12.21).
13. **Вылазка — единственная работа, где исполнителя выбирает игрок, а не симуляция.** §12.16
   («игрок размечает работу, исполнителя берёт любой свободный») здесь не нарушается, а получает
   границу: раздаётся то, что любой кот сделает одинаково, а от состава отряда зависит исход
   (§12.23). Отряд назначает `Sim::launch` в момент заявки — ровно `squad` котов, иначе отказ;
   `gather_squad` только держит их идущими к шлюзу и состав не трогает. **У `launch` двое ворот**
   (§12.43): известность — дорос ли ты вообще, репутация заказчика — станут ли с тобой говорить
   именно эти. Вылазка за своим не закрыта ни теми, ни другими. Шлюз — тайл со свойством
   `gate`, четвёртый случай схемы после `capacity`/`teaches`/`rest` (дальше идут `lab` и `tech`). **Уход — только полным
   составом**, таймер идёт с ухода, а не с заявки. Ушедший отряд не отзывается, и шлюз ему больше
   не пересматривается: коты вернутся туда, откуда ушли, даже если гараж успели снести. **Добыча
   ложится кучей на шлюз**, а не в лапы, — оттуда её разносит обычная уборка (§12.22).
14. **Исход вылазки детерминирован и считается одним выражением — `missions::outcome`.** Сила
   отряда (по коту 1 + уровень «Вылазки») против `danger`: хватило — вся добыча, не хватило —
   доля, вдвое меньше нужного — провал. Броска кубика нет **намеренно** (§12.23): с ним игрок не
   отличит «выбрал слабый отряд» от «не повезло». `outcome` зовут двое — `run_missions` на
   возвращении и `snapshot` для прогноза в панели; развести их значит показать игроку одно, а
   выдать другое. `share` мерит **четыре** вещи разом — добычу, известность, раны и репутацию
   (§12.43); пятой арифметики исхода не заводить. Той же дисциплине подчинён `trade::quote`
   (§12.44): цену спрашивают фасад в момент заказа и снапшот для панели, и разойтись им нельзя. Плата за вылазку снимается бодростью **разом на возвращении** (провал — всей):
   в поле кот не устаёт, вылазка считается, а не симулируется.
   **Провал оставляет одного кота в плену** (§12.40) — **первого по `id`**, и это ровно
   детерминизм, а не объяснение. Плен — это `Away` **без** `Squad` и не задача: кот ничего не
   делает и ничего не решает. **Причины плена игра не называет:** ни здоровье, ни навык на выбор
   не влияют, и сверх общих ран пленному не достаётся ничего — «оставили того, кому досталось
   больше» рассказывало бы, что своих раненых бросают. Само время в плену не стоит ничего: там не
   калечат и не лечат, как и в поле (§12.22).
   Две границы держат обратимость и обе живут в `run_missions`: вылазка с `rescue` пленных не
   оставляет **никогда** (иначе спираль), а обычная — только если после этого на базе хватит
   котов на самый маленький доступный спасательный отряд (`rescue_is_possible`, считается **до**
   пленения). `rescue_is_possible` смотрит только на известность и число котов **намеренно**
   (§12.43): она монотонна, а фракционные ворота умеют закрываться — с ними база, рассорившаяся
   со всеми, теряла бы кота навсегда.
   Возвращает пленных успех вылазки с `rescue` — «не провал», без долей: доля меряет
   добычу, а половины кота не бывает. Заявку на неё `Sim::launch` принимает, только пока есть
   кого спасать; самого пленного в отряд не берут — его отсекает та же проверка `Away`, что и
   ушедших.
15. **Известность (`Fame`) — ворота, а не валюта: только растёт и только открывает** (§12.24).
   Даётся той же долей, что и добыча; провал не приносит ничего, но и не отнимает — **ни
   известности, ни репутации** (§12.43): обе расходятся по сделанному. Шкала, которая
   и открывает, и тратится, закрывала бы уже доступное — игрок прочтёт это как баг. Платят за
   найм **предметы со склада**: клетка с `capacity` получает третий смысл после ёмкости и места
   назначения — казна. Котоденьги её **не заменяют** (§12.44): найм, наука и производство
   по-прежнему платят предметами, а деньги живут только на внешнем рынке. Списывается либо весь набор, либо ничего (`spend_from_storage`), а обход
   куч там отсортирован по карте: порядок сущностей ECS зависит от истории вставок и
   недетерминирован.
16. **Обучение адресно, а наука — разметка работы с допуском** (§12.18, §12.25, §12.26).
   Ученика за парту (`teaches` у тайла) сажает игрок — это решение о судьбе конкретного кота, как
   приказ «иди туда»; тему выбирает игрок, а исполнителя берёт симуляция, как у чертежа. Допуск
   («Наука» ниже `level`) **отсекает** исполнителей, и только среди оставшихся работает выбор по
   расстоянию (§12.14) — навык по-прежнему не решает, «кто лучше». Потолок обучения (`taught`)
   живёт у навыка, а не у парты: докуда доучишься — свойство домена. **Парту, как и лежанку,
   занимает один кот** (`Study::spot`), а тема, брошенная приказом или истощением, обязана явно
   очистить `Research::assignee` — иначе она навсегда останется за спящим.
17. **Событие таймлайна — единственное, что происходит без инициатора** (§12.28): не по разметке
   игрока и не по свободному коту, а потому что настал его тик (`at` — номер тика, второго
   календаря нет). У события **два исхода**: успела база к технологиям (`requires`) — груз к
   шлюзу и известность, не успела — `toll` бодрости всем, кто **на базе** (ушедших мир не
   касается, как и усталость). Срабатывает один раз, признак этого — журнал `Chronicle`, который
   только растёт. **Туман предзнания считает ядро**: до `reveal` детали и готовность в снапшот
   не кладутся вовсе.
18. **Три шкалы-ворота, и каждая отвечает на свой вопрос** (§12.24, §12.27, §12.43). Известность
   растёт от вылазок и открывает вылазки и кандидатов — то, что снаружи; технология растёт от
   науки и открывает тайлы палитры (`tech` у тайла) — то, что внутри. Обе отвечают «насколько
   высоко», **только растут и только открывают**. Репутация (`Standing`, по фракции) — третья и
   **единственная знаковая**: она отвечает «от кого» и потому умеет **закрывать**. Честной её
   держат три правила, и работают они только вместе: двигает её **только выполненный заказ**
   (той же долей `share`, что и добычу, — значит провал не двигает вовсе), она **никогда не
   платит** (валюта по-прежнему предметы), и **дорога назад есть всегда** — у каждой фракции
   обязан быть заказ, который она сама не закрывает, а нейтральная вылазка и вылазка за своим
   не закрыты никем. Последнее не украшение: фракционные ворота на `rescue` сделали бы плен
   необратимым (§12.40). Ни одна из трёх не тратится. Ворота тайла проверяются в
   `add_blueprint`, ворота вылазки и найма — в `launch`/`hire`, то есть в момент заявки:
   чертёж или заказ, который никто никогда не возьмёт, читается как поломка. Снос воротами не
   закрыт. Форма правила у вылазки — **`patron` + `against` + одно `standing`**, а не набор
   `(фракция, сколько)`: набором выразим заказ, который нравится всем, то есть фракции без
   решения (§12.43). **Котоденьги (`Money`) в этот список не входят** (§12.44): они и копятся,
   и тратятся, и ничего не открывают — это счёт, а не ворота, и «потратил, теперь не хватает»
   никто багом не назовёт.
19. **Снаряжение — свойство предмета, а надевание — задача** (§12.29, §12.34). `force` у записи
   в `items:` делает предмет надеваемым ровно так же, как `capacity` делает тайл складом; в
   кучах, в лапах и на складе он живёт как лом. Комплект коты добирают сами и **ногами**
   (`assign_equip` + `work_equip`): кот идёт к ближайшей куче — на складе или прямо на полу — и
   берёт вещь оттуда. Мгновенное списание со склада осталось только там, где это **плата**
   (найм, наука, производство): вещь, которая надета, кто-то принёс. Порядок раздачи задан явно,
   по `id` кота: когда комплектов меньше, чем котов, «кому достанется» видно игроку, а обход ECS
   недетерминирован; куча при этом считает, сколько в ней уже обещано идущим — трое за одним
   комбинезоном через полбазы это не «промах ценой ходки» (§12.15), а видимая глупость. Сила надетого входит в **тот же**
   `missions::outcome`, что и прогноз в панели (инвариант 14), а провал вылазки снаряжение
   уничтожает — успех нет.
20. **Производство — первая повторяемая работа** (§12.30). Заказ (`Craft`) — та же разметка
   работы, что чертёж и тема, но со **счётчиком штук**: очереди заказов нет. Склад платит **за
   штуку и в момент, когда за неё берутся** (в системе, а не в фасаде), поэтому заказ без
   материала не раздаётся и просто ждёт, а мастер, у которого материал отобрали, отпускается
   на другую работу. Правило списания общее с наймом и наукой (`hauling::plan_spend`) — две
   арифметики разошлись бы на порядке обхода куч. Готовое ложится **кучей под ноги** мастеру.
   Допуска по навыку у производства нет: рецепт открывает технология, «Ремесло» только ускоряет.
21. **Кот собирается ровно одним `spawn_cat`** — и стартовая тройка из `units:`, и любой новичок
   из `recruits:`. Второе место сборки означало бы кота с лапами другого размера или без
   бодрости, а заметить это можно только по странному поведению. Кандидат уникален и нанимается
   один раз; «уже нанят» спрашивается у самого кота в мире, а не у отдельного списка (§12.24).
22. **У сытости порог один, и цену голода платит бодрость** (§12.36). Ниже `hungry` кот идёт к
   ближайшей куче с едой (`nutrition` у предмета — тот же переключатель, что `force` у
   снаряжения) и съедает штуку **мгновенно по приходу**: вся длительность задачи — дорога, как у
   `Equipping`. Начатое дело голод не срывает, и второго порога у него нет **намеренно**: с
   работы кота уводит бодрость, которая на пустой желудок горит в `starve` раз быстрее (это
   единственное место, где `needs` и `food` пересекаются, — в `tire`). Голод не убивает и не
   калечит: потери котов — отдельный вопрос (§12.5) с отдельной ценой. Сытость тикает **и во
   сне** (время идёт для всех), но спящего голод не будит, а за шлюзом не считается вовсе — как
   и усталость (§12.22).

23. **Здоровье — шкала без таймера, и платит она котовременем** (§12.5, §12.37). Бодрость и
   сытость убывают за каждый прожитый тик; здоровье на базе не убывает вовсе — его роняет только
   вылазка, а возвращает только лечение. Урон считается **той же долей**, что и добыча
   (`harm * (100 - share) / 100`, всё тот же `missions::outcome`): отдельная формула развела бы
   прогноз в панели с результатом (инвариант 14). **Смерти нет:** порог `hurt` выводит кота из
   работы и из отряда, но обратимо. Ранение — единственное, что **срывает начатое** безусловно
   (усталость срывает только под свободную лежанку, §12.33), поэтому обязано пройти через
   `release_work`. Койку (`heal` у тайла) занимает один кот, лежачий переезжает на освободившуюся —
   как спящий на лежанку. **Claim медика чинится в одном месте:** `Healing::medic` снимает только
   `assign_treat`, заметив пропажу `Treating`; все, кто отбирает работу, просто снимают компонент.
   Лечить может любой кот — **допуска у «Медицины» нет** намеренно (в отличие от «Науки»): база,
   где выбывшего некому поднять, это тупик, а не сложность.

24. **Плен — первая потеря, которая сама не проходит** (§12.40, закрывает §12.5). Бодрость
   набегает во сне, раны затягиваются, комплект наберётся заново — а пленный не вернётся никогда,
   пока за ним не сходят: срок ему назначает игрок, а не таймер. Своего таймера у плена нет
   **намеренно**: он был бы первым, тикающим вне базы, и сделал бы цену функцией расторопности
   игрока с секундомером. Цена плена — отнятое котовремя: вылазка за ним. Смерти это не вводит (§12.37),
   поэтому обратимость закрыта **проверкой, а не обещанием** (см. инвариант 14). Наружу плен
   уходит отдельным флагом (`captive` у кота, `rescue` у миссии): пропажа обязана быть объяснима,
   и «ушёл на вылазку» с «остался там» — это разные решения игрока, а не одно состояние `away`.
   **Объяснима — это «его нет и его можно вернуть», а не «вот почему его оставили»:** причины
   плена в игре нет ни в коде, ни в текстах (§12.40).

25. **Котоденьги напечатать нельзя, и в этом вся торговля** (§12.44). Деньги входят единственным
   путём (продажа) и уходят единственным (покупка), поэтому **торговля не создаёт богатства, а
   меняет его состав — и всегда с убытком**: купить дороже, чем продать. Отсюда и то, что она
   не обесценивает ни вылазку, ни мастерскую. Курс — **чистая функция тика** (`trade::quote`):
   фазу выбирает время, значит расписание видно вперёд, и игрок планирует, а не караулит пик с
   секундомером (тот же довод, что у §12.40). **Курс фиксируется в момент заказа** и живёт в
   самой сделке: расписание за время поставки уйдёт, и это риск, а не ошибка. Сделка одна за
   раз, как вылазка, тема и заказ, и **отменить её нельзя** — команды для этого нет намеренно,
   иначе это бесплатный опцион. Ровно поэтому **продать можно только то, что на базе есть, и с
   заявки товар забронирован** (§12.50): слот один и не отменяется, так что сделка, которой
   нечего везти, убила бы торговлю навсегда. Бронь считается по самой сделке (`trade::booked`),
   своего поля не имеет и снимается сама, а читать её обязаны **все шесть мест, где предмет
   уходит с базы**: подвоз на площадку, плата складом (найм, наука, заказ, аптечка), еда и
   снаряжение. Потребности исключением не сделаны: проданный паёк коту не еда, а голод не
   убивает (§12.36). Покупка платится сразу и приезжает кучей на шлюз через `lead`
   тиков; продажа не платится вовсе, пока коты не донесут, и деньги капают **поштучно** по факту
   сдачи. Спред обязан перекрывать и размах фаз, и разницу курсов между фракциями — иначе
   появляется станок; стережёт это `the_shipped_ruleset_leaves_no_arbitrage`, и цифры прайса
   править только вместе с ним. Торговый пост — **лицензия, а не рабочее место**: за ним никто
   не работает, товар едет к шлюзу.

26. **Снимок покрывает всё, что не правило, и держит это сторож, а не внимательность** (§12.45).
   Сохраняется то, что изменилось с начала партии: карта, девять ресурсов состояния и компоненты
   на сущностях. **Правила не сохраняются** — 14 ресурсов-`*Rules` это разобранный YAML, их
   пересобирает `Sim::new`; сохранить их значит завести второй источник правды рядом с рулсетом.
   Отсюда обязателен **отпечаток рулсета** в файле: индексы палитр лежат в снимке числами, а
   имена — только в YAML, поэтому чужой контент даёт не ошибку, а тихо другой мир; несовпадение —
   явный отказ. Новый компонент обязан попасть в `SAVED` или в `SKIPPED` (с причиной) в
   `src/save.rs` — иначе падает `every_component_is_either_saved_or_skipped`, сверяющий реестр
   `bevy_ecs` с обоими списками **в обе стороны**. Это единственный в проекте случай, когда
   «место, которое нельзя забыть» защищено тестом, а не дисциплиной (ср. инвариант 7), и сделано
   так потому, что забытый компонент здесь **не ломает ничего** — мир после загрузки просто
   немного другой. **Ссылки на сущности** (16 полей: строитель площадки, медик, отряд, куча под
   ногой, адресат подвоза и наводка на кучу) едут номерами и раскладываются вторым проходом —
   `Entity` у нового мира свои.
   Журнал команд (`Trace`) — **отладочный слой, а не источник правды**: партию восстанавливает
   снимок, журнал только объясняет, как игрок сюда пришёл; пишется он в фасаде и нигде больше.
   **Меняешь DTO в `save.rs` — подними `FORMAT` руками:** сторож следит за составом мира, но про
   форму снимка не знает, а `#[serde(default)]` на полях `EntityDto` делает разбор снисходительным,
   и снимок с разъехавшейся схемой загрузится **молча** (пропавшее поле станет `None` — коты,
   например, приедут без бодрости). Это принятая на POC дыра, см. §12.45 и комментарий у `FORMAT`.

27. **Аптечка ускоряет лечение, но не открывает его** (§12.47). `mends` у предмета — тот же
   переключатель-свойство, что `force` и `nutrition`; отдельной сущности у аптечки нет. Платит
   склад **в момент, когда лечение началось** (в `heal`, когда медик дошёл), а не при назначении:
   оплаченное вперёд заморозило бы склад под работу, которая может не начаться (§12.30).
   Тратится **один раз на раненого** — признак этого сам `Healing::kit`, второго флага нет, — и
   прибавка держится до конца лечения, даже если медика увели: трату не отменяют. **Обязательной
   аптечка быть не может:** пустой склад означал бы «раненый не встаёт никогда», то есть тот самый
   тупик, из-за которого §12.37 отказал «Медицине» в допуске.

  спать никто не уходит и с базы тоже. Ни парты, ни лаборатории в схеме тоже нет: `teaches`,
  `taught`, `set_lab` и `set_topic` включают тесты обучения и науки сами. Снаряжения тоже нет:
  предметы бессильны (`ItemRules` пуст) и шаблон пустой (`LoadoutRules`), одеваться коты не идут.
  Ни мастерской, ни рецептов (`CraftRules` пуст) — их включает `set_shop` + `set_recipe`.
  Рынка тоже нет (денег ноль, прайсы пусты, поста в палитре нет): его включают `set_trade_post`
  + `set_market` + `set_prices` (§12.44).
  Ранений тоже нет (`HealthRules` пуст): здоровья у котов не бывает, лечиться они не ходят —
  включает `set_health_rules` (§12.37). Фракций тоже нет (`FactionRules` пуст, `Standing` пуст):
  у вылазок ни заказчика, ни пола доверия — включает `set_faction` + `set_mission_factions` /
  `set_mission_needs` (§12.43). Плена в чужих тестах тоже не случается: он требует
  вылазки с `rescue`, а её заводит `set_rescue_mission` (§12.40).
  Заставленных клеток тоже нет (`solid` у тайла схемы выключен) — их включает `set_solid`;
  а вот **завал замедляет шаг всегда**: это свойство самой кучи, а не контента (§12.35).
- Двадцать пять тестов ходят на боевой `core.yaml` (`the_shipped_ruleset_*`): уборка сноса, рост навыков
  и лапы, отправка спать, потолки сна, стройка из двух типов, успешная вылазка, заведомо провальная,
  проходимость лестницы известности, обучение «Науке», первая тема исследования, читаемость
  записки, экипировка добытым комбинезоном, деталь из лома в мастерской, заставленный стеллаж,
  лечение раненого, вылазка за пленным и шесть про фракции — дорога назад у каждой, незакрытая
  первая ступень, незакрытая вылазка за своим, достижимый пол доверия, зеркальная пара заказов
  развилка целиком и три про рынок — отсутствие арбитража, непустой прайс у каждой стороны и
  доступный торговый пост. Тем из них, что меряют запасы и известность на длинных прогонах, таймлайн выключают
  явно (`without_timeline`): мир по расписанию — это шум для чужой механики. Они ловят рассогласование кода и контента (пропавшую
  `capacity`, склад или лежанку без прохода, навык под другим `id`, забытый `carry`, порог сна
  выше потолка, критический порог выше порога усталости или забытый вовсе, предмет под
  другим `id`, гараж без `gate`, отряд больше, чем котов на базе,
  лестницу сложности, где первая вылазка невыполнима, а последняя тривиальна, порог известности,
  до которого не дойти, кандидата с опытом ниже первого порога, класс без парты или с забытым
  `taught`, лабораторию без `lab`, тему с допуском выше потолка обучения, шаблон снаряжения,
  ссылающийся на предмет не тем `id` или на предмет без `force`, мастерскую без `shop` и рецепт,
  закрытый технологией, до которой ему не дожить, вылазку без урона или с уроном, который не
  доводит до порога ранения, лазарет без `heal` или совмещённый со складом, вылазку за своим,
  закрытую известностью или требующую больше котов, чем у базы останется, — то есть плен без
  выхода; фракцию, у которой нет ни одного заказа без `needs`, — из минуса к ней не вернуться,
  первую ступень с заказчиком или полом доверия, вылазку за своим с фракционными воротами —
  то есть плен без выхода вторым путём, `needs` выше `span` — мёртвый контент, и развилку, где
  одна сторона выгоднее другой при том же усилии, то есть выбора нет; прайс, в котором где-то
  купить дешевле, чем где-то продать, — станок для печати денег, обесценивающий всю остальную
  экономику, и ловится он перебором **всех** пар фракций, фаз и при полном доверии обеим
  сторонам), которого синтетические схемы не увидят.
- В схеме `sim_from` тип один — предмет `0`, поэтому `set_cost` задаёт цену именно в нём, а тесты
  типов собирают мир явно (`set_cost_items`, `put_item`).
- Баги здесь живут во взаимодействии систем и ECS-фильтров, а не в отдельных функциях — покрывать
  механику прогоном полной цепочки (`tick_n`), а не юнит-тестом функции.
- Если конечное состояние маскирует ошибку, проверять инвариант **на каждом тике** — как в
  `demolish_job_is_done_from_a_neighbour`, где `escape_voids` иначе замёл бы след.

## Как растить фичи

Правило из §11: новая фича = **компоненты-данные** (`components.rs`) + **отдельная система**
в своём модуле, включённая в `schedule.rs::build_schedule`, минимально трогая существующие. Контент (тайлы, юниты, стартовая застройка) — в YAML, а не в коде; порядок
записей `tiles:` в рулсете = индекс палитры, который потом ходит по всему протоколу и по карте.

**Исключение — шкала-ворота** (§12.43): у `Fame`, `Techs` и `Standing` систем нет и не было
никогда. Системе нужно то, что происходит каждый тик с кем-то, а у этих трёх нет ни
сущности-владельца, ни тиков: только данные, арифметика в момент события и проверка в фасаде.
Пустую систему в цепочку ради симметрии не добавлять. Свой модуль (`src/factions.rs`) фракции
получат вместе с первым поведением по расписанию — когда начнут появляться и исчезать (§4.5).

**Второе исключение — новый адресат подвоза** (§12.44): заказ на продажу снабжается ровно как
площадка чертежа, поэтому своей раздачи не получил — он лёг в тот же список `Needy` у
`assign_hauls`, а флаг `sale` решает лишь, какой `HaulTo` выдать. Зато новый адресат обязан
попасть **во все три исчерпывающих матча по `HaulTo`**: `components.rs`, `assign_hauls` (счёт
обещанного, вместе с `assign_tidy`) и `work_hauls`. В местах, откуда задачу отбирают, матча больше нет: с §12.48
носильщик нигде не записан, кроме самого кота, и снять с него `Haul` — это всё освобождение.

**Календарь исключение не нужен, потому что он не механика** (§12.46): `day` в рулсете — это
подача, ядро о сутках не знает и ни одна система число не читает. Оно едет в `meta` и
разворачивается в «день 12» на стороне вида; тик остаётся единственными часами мира (§12.28).
Правило общее: то, что умеет влиять на симуляцию, живёт в ядре, а то, что только называет
происходящее словом, — в виде.

**Третье исключение — сохранение** (§12.45): у `save` систем нет и не будет — снимок снимается в
момент события, а не каждый тик. Зато новый компонент или ресурс состояния обязан попасть в
`SAVED` (и в сборку/разбор `save.rs`) либо в `SKIPPED` с причиной — иначе падает сторож
`every_component_is_either_saved_or_skipped`. Ресурс-`*Rules`, собираемый из YAML, всегда идёт в
`SKIPPED`: правила в снимок не сохраняются никогда.
