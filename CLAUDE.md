# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Проект ведётся на русском: документация, комментарии, doc-комментарии и сообщения коммитов —
по-русски; идентификаторы и имена тестов — по-английски. Держись этой конвенции.

## Команды

```bash
make setup   # один раз: rustup target add wasm32-unknown-unknown + npm install
make dev     # собрать WASM и поднять dev-сервер на :5173
make build   # продакшн-сборка (WASM + статика в web/dist)
make wasm    # только пересобрать ядро в web/src/wasm
make help    # список целей
```

Тесты ядра гоняются на хосте (не в wasm), обычным cargo:

```bash
cargo test
cargo test demolish              # по подстроке имени
cargo test whole_room_is_erased_completely -- --nocapture
```

Форматирование — `cargo fmt`. Сборка под wasm требует cfg-флага `getrandom_backend="wasm_js"`
из `.cargo/config.toml` — без него линковка падает; файл не удалять.

⚠️ После `make wasm` под уже запущенным Vite фронт может отдавать старую wasm-обёртку из кэша.
Перезапусти `make dev` (или почисти `web/node_modules/.vite`).

## Архитектура

Три слоя, симуляция авторитетна и детерминирована, JS — «тонкий» вид без игровой логики:

- **`src/`** — ядро по модулям; `lib.rs` держит только крейт-док, сборку модулей и `pub use Sim`.
  Данные: `ruleset` (YAML → структуры) · `map` (тайлы, проходимость, версия) · `path` (BFS) ·
  `components` (компоненты ECS и ресурсы, без поведения). Поведение: `schedule` (цепочка тика) ·
  `jobs` (чертежи) · `hauling` (перенос лома: подвоз на площадку и уборка на склад) ·
  `movement` (шаги, приказы, выход из пустоты) · `demolition` (порядок сноса) ·
  `skills` (навыки: рост от работы, скорость работы и обучение у парты) ·
  `needs` (усталость: два порога, отдых и переезд упавшего) ·
  `food` (голод: сытость, поход за пайком, вдвое горящая бодрость) ·
  `research` (наука: тема, лаборатория, технология) · `timeline` (события по расписанию) ·
  `missions` (вылазки: набор отряда, уход через шлюз, возвращение с добычей) ·
  `gear` (снаряжение: комплект по шаблону, за которым кот идёт сам) ·
  `crafting` (производство: заказ, мастерская, предмет под ноги).
  Наружу: `snapshot` (DTO) · `sim` (`#[wasm_bindgen]`-фасад). Модули приватные, публичен один `Sim`,
  поэтому внутрикрейтовые элементы помечаются `pub(crate)`.
- **`web/src/worker.js`** — WebWorker: фиксированный тик, `BASE_TPS = 6` тиков/сек на ×1,
  скорость (0·1·5·10) = множитель тиков в реальную секунду.
- **`web/src/main.js`** — PixiJS-рендер и ввод. Логики нет, только команды и отрисовка снапшота.
- **`assets/rulesets/core.yaml`** — контент в стиле OpenXcom Extended. Лежит вне `web/`;
  Vite раздаёт его через `publicDir: '../assets'` как `/rulesets/core.yaml`.

Протокол `postMessage` (полный снапшот каждый кадр — сознательное упрощение, §12.8a):

| Направление | Сообщение | Когда |
|---|---|---|
| worker → main | `ready {meta, map}` | после загрузки рулсета |
| worker → main | `map {map}` | только когда вырос `map_version()` |
| worker → main | `snapshot {snap}` | каждый кадр (~16 мс) |
| main → worker | `setSpeed {speed}` | кнопки ⏸/×1/×5/×10 |
| main → worker | `build {x, y, w, h, tile}` | `tile >= 0` → `add_blueprint_rect`, иначе `plan_demolish_rect` |
| main → worker | `store {x, y, w, h}` | рамка «на склад»: `mark_to_store_rect` |
| main → worker | `setAutoTidy {on}` | кнопка «Убирать сам» |
| main → worker | `setAutoRest {on}` | кнопка «Беречь себя»: бросает ли кот работу на исходе сил (§12.33) |
| main → worker | `move {id, x, y}` | приказ выбранному коту |
| main → worker | `launch {mission, units}` | кнопка вылазки: `launch(def, units)`, отряд выбран игроком |
| main → worker | `cancelMission` | «Отозвать» в панели миссии (только пока отряд на базе) |
| main → worker | `hire {recruit}` | кнопка найма: `hire(def)`, известность открывает, склад платит |
| main → worker | `teach {id, skill}` | кнопка обучения: `teach(unit, skill)`, кота выбирает игрок |
| main → worker | `craft {recipe, count}` | кнопка рецепта: `start_craft(def, count)`, клик — штука, Shift — пять |
| main → worker | `cancelCraft` | «Отменить» в панели заказа (материал начатой штуки не вернётся) |
| main → worker | `research {topic}` | кнопка темы: `start_research(def)`, склад платит образцами |
| main → worker | `cancelResearch` | «Бросить» в панели темы (образцы не возвращаются) |

**Цепочка систем одного тика** (`schedule.rs::build_schedule()`, `.chain()` — порядок значим):
`advance_time → collapse_exhausted → assign_eat → assign_rest → assign_equip → gather_squad →
assign_hauls → assign_research → assign_craft → assign_jobs → mark_loose_scrap → assign_tidy →
move_units → work_hauls → work_equip → work_eat → work_jobs → work_research → work_craft → study →
run_missions → run_timeline → retry_orders → escape_voids → spread_units → clear_solids →
settle_stacks → sleep → tire → hunger → train_skills`.
Цепочка собирается двумя группами (`assign` и `act`) только из-за предела арности кортежа систем;
порядок ровно тот же, что и одним списком.
Тесты гоняют ровно эту функцию, поэтому новую систему добавлять только сюда, а не в тестовую копию.
**Порядок восьми раздатчиков = приоритет работ** (§12.15, §12.16, §12.20, §12.26, §12.30, §12.34,
§12.36): все берут котов из одного пула свободных, поэтому еда идёт первой (§12.36: ходка за пайком
короткая, а сон — сотни тиков, и уснувший голодным просыпается голодным), отдых — вторым (иначе
уставшего кота тут же уводит работа), экипировка — третьей (§12.34: на базе работа есть всегда,
и поставленная после стройки она не случилась бы никогда), подвоз на площадки — четвёртым (иначе
за ломом никто не пойдёт, пока есть обеспеченная работа), наука — пятой (за тему уже заплачено
образцами, а чертёж на базе есть почти всегда), производство — шестым (заказ размечен явно и
поштучно), стройка и снос — седьмыми, уборка пола — последней.
`gather_squad` и `study` в этот порядок не входят:
и отряд, и ученика назначил игрок, и раздавать там нечего. `assign_equip` стоит **перед**
`gather_squad` и единственный берёт кота даже на маршруте, если тот в отряде: сбор ещё не
закончен, а уходить голым мимо лежащего комбинезона — это сила отряда, зависящая от расторопности
игрока (§12.34). `run_missions` стоит после
`move_units` (кот, шагнувший на шлюз, идёт в зачёт сразу) и до `settle_stacks` (добыча ложится на
шлюз, а он мог стать ямой); `study` — там же и по той же причине: кот, дошедший до парты, тикает
в этом же тике.

## Инварианты ядра

Это то, что ломается незаметно и чаще всего:

1. **Проходимость** — только построенный пол (индекс тайла `>= 0`); `-1` = пустота, непроходима,
   пересечь нельзя. Но `find_path` **не требует проходимости стартовой клетки** — на этом свойстве
   держится выход кота из ямы, менять сигнатуру осторожно.
2. **Детерминизм** — фиксированный timestep, фиксированный порядок `DIRS`, никакого рандома и
   wall-clock внутри систем. Любой недетерминизм ломает и тесты, и модель времени (§11).
3. **`BaseMap::version`** — единственный сигнал «карта изменилась»: одновременно гейт для
   `retry_orders` (не гонять BFS каждый тик) и триггер отправки `base_map` в рендер. Тайлы менять
   только через `BaseMap::set`, иначе версия не вырастет и оба механизма молча заглохнут.
4. **Снос идёт от глубины к берегу** (`DemolitionFront`), а не в порядке мазка мыши, и кот работает
   **с соседней клетки** — иначе он сносит пол под собой или отрезает себе доступ к остатку области.
5. **Приказ не срывает кота с начатой стройки**, но кот с *невыполнимым* приказом считается
   свободным для джобов — иначе он никогда не построит тайл, открывающий ему выход из запертой
   комнаты. Это была реальная регрессия; фильтры `Without<Assignment>` / `Without<Path>` в запросах
   `assign_jobs` и `retry_orders` подобраны именно под неё.
6. **`stuck` — легальное состояние, а не ошибка**: кот замурован в пустоте или его приказ пока
   невыполним. Состояние обратимо (игрок ставит пол рядом) и только подсвечивается в UI.
7. **Занятость кота — это набор фильтров, а не флаг.** Задач уже девять (`Assignment` — стройка,
   `Haul` — перенос, `Rest` — отдых, `Study` — учёба, `Researching` — наука, `Crafting` —
   производство, `Equipping` — поход за снаряжением, `Eating` — поход за едой, `Squad` — отряд), и
   каждая новая обязана попасть во все места, где кот считается свободным: `assign_eat`,
   `assign_rest`, `assign_equip`, `assign_jobs`, `assign_hauls`, `assign_research`, `assign_craft`,
   `assign_tidy`, `retry_orders`, `Busy::of` (для `is_stuck`), `spread_units`, `clear_solids`,
   а также в оба места, где задачу отбирают: `release_task` (приказ игрока, заявка на вылазку) и
   `release_work` (усталость, §12.33).
   Пропущенный `Without<…>` даёт не падение, а тихое перехватывание кота посреди работы или сна.
   Отдельно от них `Away` (кота нет на базе) режет `tire`, `hunger`, `escape_voids`,
   `collapse_exhausted` и рендер: `Squad` его уже не покрывает, потому что ушедший — всё ещё
   член отряда.
8. **Ничего не остаётся в пустоте.** Кот выходит сам (`escape_voids`), куча лома сдвигается на
   соседний пол (`settle_stacks`, он же сливает две кучи на одной клетке). Правило одно на обоих:
   пустоту не пересечь, значит оставленное в ней недостижимо, — но кот виден флагом `stuck`,
   а лом молча пропал бы (§12.15). Той же природы `spread_units`: **пройти сквозь кота можно,
   остаться в его клетке — нет** (§12.32). Кот не входит в проходимость (иначе маршруты зависели
   бы от того, кто где стоит в этот тик), поэтому правило разбирается после факта, а не запретом
   в семи раздатчиках: остаётся занятый делом, при равенстве — первый по `id`, остальные шагают
   на свободного соседа. Отряд у шлюза — исключение: сбор по определению сводит котов в одну
   точку (§12.22).
   **Материал тоже не исчезает:** отмена площадки возвращает уже сданное кучей на её клетку
   (§12.31) — в лапах носильщика груз при этом остаётся у него.
   Той же природы `clear_solids` (§12.35): на клетке со свойством `solid` (стеллаж) **пройти
   можно, остаться нельзя**. Проходимость правило не трогает — иначе стеллаж отрезал бы себя от
   носильщиков, которым сдавать груз, стоя на нём; сходят только свободные и спящие, кто при
   деле — остаётся. **Завал на полу замедляет шаг** тем сильнее, чем куча больше, до потолка
   (`CLUTTER_PER_TICK` / `CLUTTER_MAX` в `movement.rs`), и это второй смысл уборки. Считается
   только пол: сложенное в склад — порядок, а не завал. **BFS о завалах не знает** и не должен:
   он считает шаги, а не время, иначе коты обходили бы кучи, которые сами пришли разбирать, а
   «ближайший кот» в раздатчиках стал бы считаться иначе, чем видно на карте (§11, §12.35).
9. **Навык не влияет на выбор исполнителя, только на скорость работы.** Раздатчики берут
   ближайшего кота (§12.14); мастер на дальнем конце базы вернёт ровно ту беготню через
   полкарты, ради которой §12.14 и писалась. Работа считается в **очках**, а не в тиках
   (`BUILD_WORK` / `WORK_RATE`): при `progress += 1` минимальный шаг навыка — двукратное
   ускорение. Новая система работы обязана вешать `Worked(домен)` — иначе навык за неё молча
   не растёт, а начисляет опыт только `train_skills` в конце цепочки (§12.17).
10. **У бодрости два порога, и они забирают кота по-разному** (§12.20, §12.33). Выше `tired` кот
   работает; ниже — уходит спать, **но только свободным**: начатое дело обычная усталость не
   срывает, как не срывает его приказ игрока. Ниже `critical` срывает — и **только под свободную
   лежанку**: бросить дело и остаться стоять это ни сна, ни работы. На нуле кота роняет где стоит
   `collapse_exhausted`, откуда угодно и не спрашивая лежанки. Оба срыва **обязаны** явно
   освободить чертёж (`assignee`/`hauler`), пометку кучи, тему, заказ и парту — иначе площадка
   навсегда останется за спящим; поэтому освобождение живёт одной функцией (`release_work`) на
   оба случая. Второй порог выключается игроком (`AutoRest`), и выключение **никого не будит**.
   `assign_rest` раздаёт лежанки тремя проходами по одному списку свободных мест, в порядке
   нужды: критически уставшие → уставшие → **упавшие** (они уже спят, но на полу — сон там
   вшестеро медленнее, и достроенная зона отдыха обязана их касаться, §12.33). Спать можно на
   любой клетке, лежанка лишь быстрее: скорость сна не бывает нулевой, иначе кот не проснётся.
   **Лежанку занимает один кот** — занятость держит `Rest::spot` спящего (а у упавшего — его
   позиция), поэтому снимается вместе с задачей; свободной нет — кот работает до упора. Делить
   лежанки нельзя: их число тогда ни на что не влияет (§12.20).
11. **Лом не исчезает с пола «в лапы».** Кот поднимает кучу, только если знает, куда её деть, и
   берёт не больше, чем влезет в адресат. Груз в лапах игроку не виден как ресурс и не
   размечается — то, что лежит на полу, всегда можно достать (§12.16). Сумма
   «кучи + лапы + `delivered`» сохраняется; на ней держатся тесты уборки.
12. **Тип предмета — индекс палитры `items:`, и он лежит в куче, в грузе и в цене тайла.** Цена —
   **набор** `(предмет, сколько)`, упорядоченный по имени предмета (`BTreeMap` в рулсете): порядок
   доходит до раздачи задач, а `HashMap` сделал бы её недетерминированной. Кот везёт **один тип за
   ходку**, кучи разных типов лежат на одной клетке и не сливаются, а склад типо-агностичен —
   ёмкость считает штуки (§12.21).
13. **Вылазка — единственная работа, где исполнителя выбирает игрок, а не симуляция.** §12.16
   («игрок размечает работу, исполнителя берёт любой свободный») здесь не нарушается, а получает
   границу: раздаётся то, что любой кот сделает одинаково, а от состава отряда зависит исход
   (§12.23). Отряд назначает `Sim::launch` в момент заявки — ровно `squad` котов, иначе отказ;
   `gather_squad` только держит их идущими к шлюзу и состав не трогает. Шлюз — тайл со свойством
   `gate`, четвёртый случай схемы после `capacity`/`teaches`/`rest` (дальше идут `lab` и `tech`). **Уход — только полным
   составом**, таймер идёт с ухода, а не с заявки. Ушедший отряд не отзывается, и шлюз ему больше
   не пересматривается: коты вернутся туда, откуда ушли, даже если гараж успели снести. **Добыча
   ложится кучей на шлюз**, а не в лапы, — оттуда её разносит обычная уборка (§12.22).
14. **Исход вылазки детерминирован и считается одним выражением — `missions::outcome`.** Сила
   отряда (по коту 1 + уровень «Вылазки») против `danger`: хватило — вся добыча, не хватило —
   доля, вдвое меньше нужного — провал. Броска кубика нет **намеренно** (§12.23): с ним игрок не
   отличит «выбрал слабый отряд» от «не повезло». `outcome` зовут двое — `run_missions` на
   возвращении и `snapshot` для прогноза в панели; развести их значит показать игроку одно, а
   выдать другое. Плата за вылазку снимается бодростью **разом на возвращении** (провал — всей):
   в поле кот не устаёт, вылазка считается, а не симулируется.
15. **Известность (`Fame`) — ворота, а не валюта: только растёт и только открывает** (§12.24).
   Даётся той же долей, что и добыча; провал не приносит ничего, но и не отнимает. Шкала, которая
   и открывает, и тратится, закрывала бы уже доступное — игрок прочтёт это как баг. Платят за
   найм **предметы со склада**: клетка с `capacity` получает третий смысл после ёмкости и места
   назначения — казна. Списывается либо весь набор, либо ничего (`spend_from_storage`), а обход
   куч там отсортирован по карте: порядок сущностей ECS зависит от истории вставок и
   недетерминирован.
16. **Обучение адресно, а наука — разметка работы с допуском** (§12.18, §12.25, §12.26).
   Ученика за парту (`teaches` у тайла) сажает игрок — это решение о судьбе конкретного кота, как
   приказ «иди туда»; тему выбирает игрок, а исполнителя берёт симуляция, как у чертежа. Допуск
   («Наука» ниже `level`) **отсекает** исполнителей, и только среди оставшихся работает выбор по
   расстоянию (§12.14) — навык по-прежнему не решает, «кто лучше». Потолок обучения (`taught`)
   живёт у навыка, а не у парты: докуда доучишься — свойство домена. **Парту, как и лежанку,
   занимает один кот** (`Study::spot`), а тема, брошенная приказом или истощением, обязана явно
   очистить `Research::assignee` — иначе она навсегда останется за спящим.
17. **Событие таймлайна — единственное, что происходит без инициатора** (§12.28): не по разметке
   игрока и не по свободному коту, а потому что настал его тик (`at` — номер тика, второго
   календаря нет). У события **два исхода**: успела база к технологиям (`requires`) — груз к
   шлюзу и известность, не успела — `toll` бодрости всем, кто **на базе** (ушедших мир не
   касается, как и усталость). Срабатывает один раз, признак этого — журнал `Chronicle`, который
   только растёт. **Туман предзнания считает ядро**: до `reveal` детали и готовность в снапшот
   не кладутся вовсе.
18. **Две шкалы-ворота, и каждая открывает своё** (§12.24, §12.27). Известность растёт от вылазок
   и открывает вылазки и кандидатов — то, что снаружи; технология растёт от науки и открывает
   тайлы палитры (`tech` у тайла) — то, что внутри. Обе **только растут и только открывают**, и
   ни одна не тратится. Ворота тайла проверяются в `add_blueprint`, то есть в момент разметки:
   чертёж, который никто никогда не возьмёт, читается как поломка. Снос воротами не закрыт.
19. **Снаряжение — свойство предмета, а надевание — задача** (§12.29, §12.34). `force` у записи
   в `items:` делает предмет надеваемым ровно так же, как `capacity` делает тайл складом; в
   кучах, в лапах и на складе он живёт как лом. Комплект коты добирают сами и **ногами**
   (`assign_equip` + `work_equip`): кот идёт к ближайшей куче — на складе или прямо на полу — и
   берёт вещь оттуда. Мгновенное списание со склада осталось только там, где это **плата**
   (найм, наука, производство): вещь, которая надета, кто-то принёс. Порядок раздачи задан явно,
   по `id` кота: когда комплектов меньше, чем котов, «кому достанется» видно игроку, а обход ECS
   недетерминирован; куча при этом считает, сколько в ней уже обещано идущим — трое за одним
   комбинезоном через полбазы это не «промах ценой ходки» (§12.15), а видимая глупость. Сила надетого входит в **тот же**
   `missions::outcome`, что и прогноз в панели (инвариант 14), а провал вылазки снаряжение
   уничтожает — успех нет.
20. **Производство — первая повторяемая работа** (§12.30). Заказ (`Craft`) — та же разметка
   работы, что чертёж и тема, но со **счётчиком штук**: очереди заказов нет. Склад платит **за
   штуку и в момент, когда за неё берутся** (в системе, а не в фасаде), поэтому заказ без
   материала не раздаётся и просто ждёт, а мастер, у которого материал отобрали, отпускается
   на другую работу. Правило списания общее с наймом и наукой (`hauling::plan_spend`) — две
   арифметики разошлись бы на порядке обхода куч. Готовое ложится **кучей под ноги** мастеру.
   Допуска по навыку у производства нет: рецепт открывает технология, «Ремесло» только ускоряет.
21. **Кот собирается ровно одним `spawn_cat`** — и стартовая тройка из `units:`, и любой новичок
   из `recruits:`. Второе место сборки означало бы кота с лапами другого размера или без
   бодрости, а заметить это можно только по странному поведению. Кандидат уникален и нанимается
   один раз; «уже нанят» спрашивается у самого кота в мире, а не у отдельного списка (§12.24).
22. **У сытости порог один, и цену голода платит бодрость** (§12.36). Ниже `hungry` кот идёт к
   ближайшей куче с едой (`nutrition` у предмета — тот же переключатель, что `force` у
   снаряжения) и съедает штуку **мгновенно по приходу**: вся длительность задачи — дорога, как у
   `Equipping`. Начатое дело голод не срывает, и второго порога у него нет **намеренно**: с
   работы кота уводит бодрость, которая на пустой желудок горит в `starve` раз быстрее (это
   единственное место, где `needs` и `food` пересекаются, — в `tire`). Голод не убивает и не
   калечит: потери котов — отдельный вопрос (§12.5) с отдельной ценой. Сытость тикает **и во
   сне** (время идёт для всех), но спящего голод не будит, а за шлюзом не считается вовсе — как
   и усталость (§12.22).

## Тесты

242 теста живут в `src/tests/` по механикам (`paths` · `voids` · `orders` · `jobs` · `demolition` ·
`hauling` · `tidying` · `skills` · `study` · `research` · `needs` · `food` · `items` · `missions` · `fame` · `terrain` ·
`timeline` · `gear` · `crafting` · `crowd`); общие хелперы и сборка мира —
в `tests/mod.rs`. Мир собирается из ASCII-схем, минуя YAML:

```rust
let mut sim = sim_from(&["#####", "#a..#", "#####"]); // '#' пустота, '.' пол, буква — кот с этим id
```

- Крупные схемы — в `src/test_maps/*.map` через `include_str!("../test_maps/…")` + `rows_from()`:
  `rustfmt` схлопывает многострочные массивы строк в одну строку и делает схему нечитаемой.
- Хелперы на `Sim` под `#[cfg(test)]`: `tick_n`, `pos_of`, `stuck_of`, `has_assignment`, `has_path`,
  `has_haul`, `tile`, `force_tile`, `map_ver`, `order_tried_version`, `plan_demolish_rect`,
  `floors_left`; по материалу — `set_cost`, `set_capacity`, `put_scrap`, `scrap_at`, `scrap_total`,
  `scrap_is_on_floor`, `scrap_is_in_storage`, `carrying_of`, `delivered_at`; по навыкам —
  `set_skill`, `set_xp`, `xp_of`, `level_of`, `skill_index`, `set_carry`, `carry_max_of`;
  по усталости — `set_needs`, `set_critical`, `thresholds`, `set_rest`, `set_energy`, `energy_of`,
  `is_resting`, `rest_spot_of`; по типам —
  `set_cost_items`, `put_item`, `item_at`, `item_total`, `carrying_item_of`, `delivered_item_at`;
  по вылазкам — `set_gate`, `set_mission`, `set_risky_mission`, `in_squad`, `is_away`,
  `mission_left`, `mission_gate`; по известности и найму — `fame`, `set_fame`, `set_mission_fame`,
  `set_recruit`, `has_unit`; по обучению — `set_teaches`, `set_taught`, `is_studying`, `desk_of`;
  по науке — `set_lab`, `set_topic`, `set_tile_tech`, `knows_tech`, `set_tech`,
  `research_progress`, `researcher`, `is_researching`; по таймлайну — `set_event`, `set_reveal`,
  `happened`, `note_revealed`, `note_requires`, `note_ready`, `without_timeline`; по снаряжению —
  `set_force`, `set_loadout`, `gear_of`, `is_equipping`, `take_item`; по клетке — `set_solid`,
  `solid_tiles`, `capacity_of`;
  по производству — `set_shop`, `set_recipe`, `craft_left`,
  `craft_progress`, `crafter`, `is_crafting`.
- **`add_blueprint(x, y, 0)` в схеме `sim_from` — пустышка:** пол схемы это уже тайл `0`, и
  чертёж отсекается как «уже построено». Тест с ним зелёный и ничего не проверяет (наступали).
  Занимать кота стройкой — любым другим индексом, как `OTHER` в `tests/missions.rs`.
- Тайл в `sim_from` **бесплатен, не склад и не шлюз** (`TileRules` = нули): цена и ёмкость —
  контент рулсета, и тесты механик, не связанных с материалом, о нём не знают. Тесты переноса и
  уборки задают свойства явно (`set_cost`, `set_capacity` + `force_tile`). Ровно так же нет
  навыков (`SkillRules` пуст), предела лап и усталости (`NeedRules` пуст, бодрости у котов нет),
  и вылазок (`MissionRules` пуст): работа идёт с базовой скоростью, `BUILD_TICKS` тиков на тайл,
  спать никто не уходит и с базы тоже. Ни парты, ни лаборатории в схеме тоже нет: `teaches`,
  `taught`, `set_lab` и `set_topic` включают тесты обучения и науки сами. Снаряжения тоже нет:
  предметы бессильны (`ItemRules` пуст) и шаблон пустой (`LoadoutRules`), одеваться коты не идут.
  Ни мастерской, ни рецептов (`CraftRules` пуст) — их включает `set_shop` + `set_recipe`.
  Заставленных клеток тоже нет (`solid` у тайла схемы выключен) — их включает `set_solid`;
  а вот **завал замедляет шаг всегда**: это свойство самой кучи, а не контента (§12.35).
- Тринадцать тестов ходят на боевой `core.yaml` (`the_shipped_ruleset_*`): уборка сноса, рост навыков
  и лапы, отправка спать, стройка из двух типов, успешная вылазка, заведомо провальная,
  проходимость лестницы известности, обучение «Науке», первая тема исследования, читаемость
  записки, экипировка добытым комбинезоном, деталь из лома в мастерской и заставленный стеллаж. Тем из них, что меряют запасы и известность на длинных прогонах, таймлайн выключают
  явно (`without_timeline`): мир по расписанию — это шум для чужой механики. Они ловят рассогласование кода и контента (пропавшую
  `capacity`, склад или лежанку без прохода, навык под другим `id`, забытый `carry`, порог сна
  выше потолка, критический порог выше порога усталости или забытый вовсе, предмет под
  другим `id`, гараж без `gate`, отряд больше, чем котов на базе,
  лестницу сложности, где первая вылазка невыполнима, а последняя тривиальна, порог известности,
  до которого не дойти, кандидата с опытом ниже первого порога, класс без парты или с забытым
  `taught`, лабораторию без `lab`, тему с допуском выше потолка обучения, шаблон снаряжения,
  ссылающийся на предмет не тем `id` или на предмет без `force`, мастерскую без `shop` и рецепт,
  закрытый технологией, до которой ему не дожить), которого синтетические схемы не увидят.
- В схеме `sim_from` тип один — предмет `0`, поэтому `set_cost` задаёт цену именно в нём, а тесты
  типов собирают мир явно (`set_cost_items`, `put_item`).
- Баги здесь живут во взаимодействии систем и ECS-фильтров, а не в отдельных функциях — покрывать
  механику прогоном полной цепочки (`tick_n`), а не юнит-тестом функции.
- Если конечное состояние маскирует ошибку, проверять инвариант **на каждом тике** — как в
  `demolish_job_is_done_from_a_neighbour`, где `escape_voids` иначе замёл бы след.

## Как растить фичи

Правило из §11: новая фича = **компоненты-данные** (`components.rs`) + **отдельная система**
в своём модуле, включённая в `schedule.rs::build_schedule`, минимально трогая существующие. Контент (тайлы, юниты, стартовая застройка) — в YAML, а не в коде; порядок
записей `tiles:` в рулсете = индекс палитры, который потом ходит по всему протоколу и по карте.
